# bbdc-to-ai 代码审查

以 v1.6.0 为基线，审查 Python 数据与导出、桌面任务与三种界面、Windows 打包与升级、GitHub Pages 和回归测试。Codex 对照源码与合成用例核实，Gemini 审查公开源码快照并起草前端提示词，DeepSeek 复核公开仓库的主要入口。设备集成只做源码与模拟测试，没有在真实 MuMu 会话或用户学习记录上试跑。

## 已修复

| 发现 | 修复 |
| --- | --- |
| 用户要中断同步只能关窗口，关窗时也可能跳过未保存草稿确认 | 同一按钮支持停止，保留预览和草稿。开始写入时等待结果。Flutter 在关窗前仍会询问草稿。 |
| Flutter 轮询和停止请求写同一管道时可能重叠，异常回复也可能使等待中的请求挂起 | 串行发送并让管道中断或格式错误通知等待中的请求。 |
| 旧配置省略可选布尔字段或历史窗口超过合法日期范围时，读取可能报错 | 采用原解析器的缺省值，历史查询将日期限制在有效范围。 |
| 分档练习切出页面后，同一日期的结果与选项会丢失 | 同一日期和目录保留页面状态。 |
| 主页复制的是旧版固定考研模板，部分测试读本机配置 | 用现行导出器重生成合成示例，测试使用公开模板和临时目录。 |

## 后续维护

- **重导出覆盖手工编辑**。同步或重新导出会重写同日 Markdown。现有保存会检测草稿冲突。自动生成方向还没有同样的编辑保护，后续可对照上次生成的版本并保留手改副本。涉及 `src/exporter.py`、`src/desktop_files.py`。
- **写入中途发生磁盘故障**。每日缓存、SQLite 和 Markdown 各自写入。已提交的历史和稍后失败的 Markdown 可能显示不同步。建议单独测试每个写入阶段的失败和重试，对可恢复的产物明确重建顺序。涉及 `src/pipeline.py`、`src/history.py`。
- **模块边界**。分档练习和每日导出已有各自的业务入口。Flutter 与 WebView 共用后台任务入口，Tk 仍自行处理部分轮询。后续可以共享任务结果与清理接口，再把窗口里较长的工具栏和弹窗协调拆成小组件。涉及 `src/desktop_jobs.py`、`src/desktop.py`、`flutter_ui/lib/shell.dart`。
- **同版本重打包**。自动安装以版本号选取已安装副本。修复应递增版本并发布新标签，版本相同的下载包可能继续对应原来的桌面快捷方式。涉及 `src/desktop_install.py`、`packaging/windows_entry.py`。

复核时排除了部分模型推测。历史库查询按调用建立并关闭连接，未找到建议所称的跨线程共享连接。Markdown 已使用临时文件和原子替换。官网的 `docs/app.js` 与打包给桌面 WebView 的 `frontend/bundle.js` 是不同入口。
