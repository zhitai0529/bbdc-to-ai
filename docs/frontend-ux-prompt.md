# Flutter 桌面交互优化 Prompt

你负责优化「不背单词复习助手」的 Windows Flutter 界面。使用现有 Material 3 主题和控件。先阅读 `flutter_ui/lib` 的窗口、导航、复习会话、后台任务和分档练习代码，再用 860×600 和 1440×900 两种窗口尺寸走一遍「选择日期 → 同步或停止 → 预览或练习 → 复制」。

借鉴 TsumugiSub 的局部工具栏、选中项反馈和后台操作的生命周期。将它的桌面可用部分转化为键盘和鼠标交互。 [TsumugiSub 编辑器演示](https://nihaina.github.io/SubtitleEditforAndroid/#editor-demo) · [后台任务说明](https://github.com/nihaina/SubtitleEditforAndroid/blob/main/docs/background-tasks.md)

## 实现要求

- **操作层级**。保留顶栏日期与同步入口。复习预览的复制、保存与阅读模式靠近正文。练习页的题型、生成和复制靠近练习预览。窄窗口工具组有序换行，按钮换文案时尽量维持当前位置。
- **任务反馈**。复用 `DesktopTasks`。在同一位置显示「同步 MuMu」「停止同步」「正在停止」或「正在收尾」。按钮状态由后台结果驱动，等待过程中给局部进度和可读状态。一次结果只需一次可见通知，遇到需要用户选择的情况再弹对话框。保持每日离线导出和练习的现有工作流。
- **导航与动效**。保留同一日期、同一目录下的草稿和练习预览。日期或者目录切换时，只使对应旧结果失效。为导航和按钮补齐键盘焦点、工具提示与读屏名称。必要的局部过渡用约 150–200ms，并遵循系统减少动态效果的设置。
- **空态**。无学习记录、无待复习词、缓存不可读、导出失败分别说清发生了什么和下一步。复用现有日夜主题，避免为不同页面新增成套组件。

## 验收

用合成数据核对最小窗口、宽窗口、日夜主题和纯键盘导航。同步期间能停止，已开始存盘时可正常收尾，快速重复点击只产生一次请求。切换页面后未保存草稿仍在，练习预览对应所选日期和档位。截图或录屏应包含空态、进行中和完成状态。提交前运行 `flutter analyze` 和 `flutter test`，保留现有 `HostCall` 与 Python 后端调用契约。
